Find the mistakes your coding agent keeps repeating.

Every session starts with no memory of your machine, so the agent calls the program that isn't installed, imports from the wrong Python and trips on the same shell quirk, week after week. Drop your Claude Code or Codex logs here to see which mistakes repeat and the one line that fixes each.

The analysis runs in this tab. Your logs are never uploaded.

Where are my logs?

Claude Code keeps them in ~/.claude/projects, and Codex CLI in ~/.codex/sessions. Both folders start with a dot, so the file picker hides them. On a Mac, press Cmd+Shift+. in the picker to show hidden folders, then choose .claude or .codex in your home folder.

Or run this in a terminal. It zips only the log files and your two global instruction files, so the report can also measure lines you already added.

cd ~ && zip -qr ~/Desktop/agent-logs.zip .claude/projects .codex/sessions .claude/CLAUDE.md .codex/AGENTS.md -i '*.jsonl' '*/CLAUDE.md' '*/AGENTS.md'

Then choose agent-logs.zip on your Desktop. Large histories (hundreds of MB) take a minute; nothing leaves your machine either way.

How it decides

A repeated mistake
A failed tool call whose last error line matches a failure in another session, ignoring numbers and ids. Failing test runs don't count; the agent is checking its work.
The fix
One line for your agent's instruction file, from a rule written for that kind of mistake. The command-line version can add it for you and block known mistakes live in Claude Code.
Did it work
Lines added by orchestra-review apply carry a timestamp. The report counts only sessions that tried the same action, before and after, so a change of task can't pass for a cure.

In 67,074 public coding-agent runs across 1,823 repositories, 41% of failures with an identifiable cause repeated a mistake seen in another repository. Method and limits.
